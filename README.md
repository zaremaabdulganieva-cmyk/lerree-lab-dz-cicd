# Lerree Lab — кабинет участницы: backend и интеграция

ДЗ 5 курса про ИИ-агентов: **«Развертывание Backend и интеграция с
Frontend»**.

Личный кабинет участницы фитнес-клуба, подключённый к настоящей базе
данных. Интерфейс сделан в [ДЗ 4](https://github.com/zaremaabdulganieva-cmyk/lerree-lab-dz-frontend)
и работал на выдуманных данных; здесь под него поднята база, написаны
миграции и политики доступа, а данные из кода убраны.

Проект учебный, содержимое вымышленное. Боевой Lerree Lab с платным
контентом клуба живёт в закрытом репозитории.

**Демонстрация:** <https://zaremaabdulganieva-cmyk.github.io/lerree-lab-dz-backend/>

## Стек

- **База:** PostgreSQL в Supabase, 7 таблиц + представление, политики
  Row Level Security
- **API:** автоматический REST поверх таблиц (PostgREST) + Supabase Auth
- **Интерфейс:** React 19, TypeScript, Tailwind 4, React Router
- **Проверки:** Vitest — 59 тестов, плюс SQL-скрипт проверки политик
- **Публикация:** GitHub Pages через GitHub Actions

## Быстрый старт

```bash
npm install
cp .env.example .env    # вписать адрес проекта и публичный ключ
npm run dev
```

Где взять адрес и ключ — [docs/setup-supabase.md](docs/setup-supabase.md).

Прогнать проверки:

```bash
npm test                                          # тесты приложения
psql "<строка подключения>" -f scripts/check-rls.sql   # проверка доступа
```

Локальная песочница базы (не требует облака):

```bash
docker compose up -d
```

## Что внутри

```
supabase/migrations/   миграции: таблицы, политики доступа, наполнение
scripts/check-rls.sql  12 проверок безопасности на живой базе
scripts/remove-demo.sql  уборка: удаляет демо из общего проекта Supabase
scripts/create-demo-users.sql  демо-участницы одним запросом
docker/                заглушка служебной схемы для локальной песочницы
docker-compose.yml     локальный PostgreSQL одной командой
src/lib/supabase.ts    подключение (адрес и ключ — только из окружения)
src/lib/api.ts         все запросы к базе; экраны про Supabase не знают
src/lib/errors.ts      перевод ошибок сервера на человеческий язык
src/lib/logger.ts      журнал событий
src/pages/             экраны кабинета
```

## Безопасность в двух словах

Правила доступа лежат в базе, а не в приложении. Приложение в браузере
можно изучить и подделать любой его запрос — поэтому оно ничего не
решает: кто что видит, определяют политики PostgreSQL. Участница с
истёкшей подпиской не получит контент даже обращением к API напрямую, а
чужие замеры не видны никому.

Секретов в репозитории нет: публичный ключ подставляется при сборке из
окружения, `.env` в git не попадает, секретный ключ `service_role` в
приложении не используется вовсе.
