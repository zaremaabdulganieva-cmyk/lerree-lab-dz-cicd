# Как поднять базу — пошагово

Инструкция на один раз, минут на пятнадцать. Ничего программировать не
нужно: только нажимать кнопки и вставлять готовый текст.

Демо живёт в уже существующем проекте **fingram-studio**
(`lxmanoogouyehmahnkuy`). Боевую базу клуба не трогаем: содержимое
здесь вымышленное.

---

## Шаг 1. Открыть проект

<https://supabase.com/dashboard/project/lxmanoogouyehmahnkuy>

### Почему соседство с fingram безопасно

Проверено на копии: сначала поставлена схема fingram, потом наши
миграции, потом сверка.

- **Имена не пересекаются.** У fingram таблицы `posts`, `ideas`,
  `radar`, `config`, `meta`, `log`; у демо — свои семь. Общих функций и
  триггеров нет.
- **Данные не видны друг другу.** Демо-участница, вошедшая в кабинет,
  видит 0 постов и 0 идей fingram. Гость — тоже 0.
- **Права fingram не меняются.** Защита и разрешения на всех шести его
  таблицах до и после миграций совпадают строка в строку.
- **Вход fingram не задет.** У студии свой пароль, а не вход Supabase,
  поэтому демо-участницы в списке пользователей проекта ей не мешают.

В **Table Editor** теперь будут видны таблицы обоих приложений —
это нормально.

После сдачи курса демо убирается одним скриптом — см. «Уборка» в конце.

---

## Шаг 2. Выполнить миграции

Открыть слева **SQL Editor** → **New query**.

Дальше четыре файла из папки `supabase/migrations`. Каждый — отдельно:
открыть файл, скопировать целиком, вставить в редактор, нажать **Run**,
дождаться зелёного `Success`. И только потом браться за следующий.

Порядок важен:

1. `001_init_schema.sql` — создаёт таблицы
2. `002_rls_policies.sql` — включает правила доступа
3. `003_seed_content.sql` — добавляет программу и материалы

Четвёртый файл пока **не** запускаем — сначала шаг 3.

## Шаг 3. Создать двух демо-участниц

Слева **Authentication** → **Users** → **Add user** → **Create new user**.

Первая:

- Email: `anna@demo.ru`
- Password: `demo1234`
- Галочка **Auto Confirm User** — включить

То же самое для второй:

- Email: `olga@demo.ru`
- Password: `demo1234`
- Галочка **Auto Confirm User** — включить

Галочка важна: без неё Supabase будет ждать, пока участница подтвердит
адрес письмом, и вход не сработает.

**Быстрее — одним запросом:** вместо кликов выполнить в SQL Editor
`scripts/create-demo-users.sql`. Он заведёт обеих участниц сразу
подтверждёнными. Так и было сделано при настройке демо.

Теперь вернуться в **SQL Editor** и выполнить четвёртый файл:

4. `004_demo_users.sql` — проставит Анне активную подписку, Ольге
   истёкшую и добавит историю замеров и тренировок

Если он ругнётся «Сначала создайте пользователей» — значит, участницы
не завелись; проверить шаг 3.

## Шаг 4. Забрать два значения

Слева **Settings** (шестерёнка) → **API**. Нужны:

- **Project URL** — вид `https://abcdefgh.supabase.co`
- **Project API keys → anon public** — длинная строка

Эти два значения можно спокойно присылать мне и класть в настройки:
они не секретные, их видно в браузере у любой участницы. Данные
защищает не ключ, а правила доступа в базе.

**А вот `service_role` — не трогать и никому не отправлять.** С ним
правила доступа не действуют.

---

## Шаг 5. Прописать значения приложению

Локально, в папке проекта:

```bash
cp .env.example .env
```

Открыть `.env` и вписать оба значения. Проверить:

```bash
npm run dev
```

Открыть <http://localhost:5173>, войти как `anna@demo.ru` / `demo1234`.
Должны появиться программа, материалы и замеры.

---

## Шаг 6. Секреты для публикации

Чтобы приложение собиралось на GitHub:

**Settings → Secrets and variables → Actions → New repository secret**,
и добавить два:

- `VITE_SUPABASE_URL` — тот же Project URL
- `VITE_SUPABASE_ANON_KEY` — тот же ключ anon

## Проверка, что всё правильно

**Settings → Database → Connection string** → скопировать строку
подключения (в ней надо подставить пароль базы fingram-studio; если он
потерян — там же **Reset database password**, но тогда нужно обновить
его и в настройках fingram, если он где-то используется) и выполнить:

```bash
psql "<строка подключения>" -f scripts/check-rls.sql
```

Последняя строка ответа должна быть `ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`. Если
какая-то строка помечена `ПРОВАЛ` — прислать мне вывод целиком.

## Если что-то пошло не так

**«Invalid login credentials» при входе.** Участница не заведена или не
подтверждена: Authentication → Users, проверить, что она есть и не висит
как *Waiting for verification*.

**Вошли, но экраны пустые.** Не выполнена миграция 003 (нет контента)
или у участницы истекла подписка. Проверить в SQL Editor:

```sql
select name, subscription_status, subscription_until from profiles;
```

**«Приложение собрано без подключения к базе».** Не заполнен `.env`
(локально) или не заданы секреты репозитория (на GitHub Pages).

**Страница белая после публикации.** Обычно это адрес: приложение
собирается для пути `/lerree-lab-dz-backend/`. Проверить, что имя
репозитория совпадает с `REPO_NAME` в `vite.config.ts`.

---

## Уборка после курса

Когда ДЗ принято и демо больше не нужно: **SQL Editor** → выполнить
`scripts/remove-demo.sql`.

Скрипт удаляет только то, что создали наши миграции, — по списку, а не
«всё подряд»: семь таблиц, представление, функции, типы и двух
демо-участниц. Проверено на копии: таблицы fingram, его данные и права
после уборки остаются нетронутыми.
